> 准备日期：2026-11-24
> 状态：**材料已就绪，尚未送审**。这是进入 Phase 1 完整开发的硬门槛。

---

## 1. 评审目标

确认本系统的零知识架构在实际代码与协议层面成立，特别是：

- 平台在任何时刻都无法解密客户业务数据；
- 密钥派生、包裹、轮换、恢复流程没有可绕过的安全缺陷；
- 审计链无法被平台或租户内成员篡改、分叉或回滚而不被发现；
- 多租户之间不存在任何形式的密钥或密文串用。

这不是一次常规 Web 渗透测试，而是**协议级评审 + 关键实现审查**。

## 3. 评审范围边界

**在范围内：**

- OPAQUE 的 `export_key` 用作 KEK 派生输入是否合规；
- Argon2id 参数、HKDF info 标签、AES-GCM AAD 绑定；
- Shamir 2-of-3 的分片展示、校验与内存擦除流程；
- TK / UK / VK / DEK / AK 的包裹层次与四类轮换流程；
- 审计链哈希公式、并发顺序一致性、创世与外部锚定；
- 设备签名 Payload 的构造与防重放（当前 Payload **尚未包含随机挑战或时间戳**，见问题 Q7）。

**不在范围内（本轮）：**

- 前端 XSS / CSP 配置的完整渗透测试（Phase 1 单独做）；
- 基础设施、WAF、对象存储配置审计（Phase 3）；
- 合规与法务判断（个保法、等保、商密）。

---

## 4. 评审交付期望

请评审方提供：

1. **书面报告**：逐项回答 `review-questions.md` 中的问题；
2. **缺陷分级**：严重 / 高 / 中 / 低，含可复现步骤或证明思路；
3. **明确结论**：是否同意进入 Phase 1 开发（同意 / 附条件同意 / 不同意）；
4. **签署版本**：注明所评审的文档与代码版本（当前为 v0.1 / commit 前的当前文件状态）。

**准入判据：** 无严重或高危缺陷；所有中危缺陷有明确的修复方案与责任人。

---

## 5. 保密与独立性

- 评审方应独立于平台运营方，且不在客户组织中持有管理员角色；
- 本材料包不含任何真实租户数据、真实密钥或恢复分片；所有向量均为构造值；
- 评审方可要求补充 Threat Model 中未覆盖的攻击面，我们应配合提供。
